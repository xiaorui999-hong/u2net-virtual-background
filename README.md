# U²-Net 虚拟背景程序（PyQt5）

基于 **U²-Net 人物分割模型** 的实时虚拟背景程序，使用 PyQt5 构建图形界面。支持摄像头切换、图片或纯色背景、阈值调节、镜像、截图保存、录制带声音的视频，以及带语音对讲的局域网会议。

程序针对 Windows + CUDA 环境优化，支持 GPU 加速与 FP16 推理；没有 CUDA 时会自动回退到 CPU。

## 功能特性

- 实时人物分割：基于 U²-Net 高质量人物抠图，边缘平滑。
- 虚拟背景合成：支持图片背景和纯色背景，实时 Alpha 合成。
- 摄像头切换：支持多摄像头（默认 `0`，外接设备通常为 `1`）。
- 实时参数调节：阈值、水平镜像、输入尺寸（192 / 256 / 320 / 384）。
- 模型选择：可浏览选择任意 `.pth` / `.pt` 权重。
- 设备选择：自动选择 CUDA 或 CPU，CUDA 下可启用 FP16。
- 保存当前画面：一键保存带时间戳的 JPG。
- 视频录制：支持无声录制，以及借助 `sounddevice` + `ffmpeg` 的带声音录制。
- 局域网会议：支持创建会议主机或加入同一局域网的主机，**人数上限可在界面上设置**（2–50 人，含主机），同时传输视频画面与语音。
- 两种画面模式：**逐路转发**画质最好、适合小会；**合成画面**由主机拼成一张多宫格图，主机上行带宽随人数线性增长，几十人也能开。
- 会议语音对讲：16 kHz 单声道 PCM，进会即能听到他人，默认闭麦；点“开麦”才上传自己的麦克风。可在界面选择麦克风与扬声器、调节输出音量。
- 自适应轻量传输：会议画面缩放至 480 × 270，以 JPEG 压缩后按 8 / 10 / 12 / 15 FPS 发送；接收端本地解码显示，慢连接自动丢弃旧帧以降低延迟。
- 语音与画面分开排队：控制与语音走优先发送队列，视频单独排队且只保留最新两帧，因此慢连接丢的是过期画面而不是语音。
- 安全检查：摄像头、模型、背景图、保存目录均进行有效性检查。
- 异常保护：空帧、CUDA 回退、模型输出维度异常等情况不会导致程序崩溃。
- 性能优化：后台读取与推理、隔帧更新掩码、摄像头缓冲区设为 1，并使用 PIL 缩放规避 OpenCV 5.0.0 的 `cv2.resize` HAL 问题。

| PyTorch | 2.5.1（建议 CUDA 环境使用对应版本）   |

| OpenCV | `opencv-python` 4.x 或 5.x |

## 安装

### 1. 安装 Python 依赖

```bash
pip install PyQt5 opencv-python pillow numpy torch torchvision sounddevice
```

如需 GPU 加速，请按 CUDA 版本安装匹配的 PyTorch。以下是 CUDA 12.8 示例：

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```

### 2. 安装 ffmpeg（录制声音需要）

1. 从 [gyan.dev ffmpeg builds](https://www.gyan.dev/ffmpeg/builds/) 下载 `ffmpeg-release-essentials.zip`。
2. 解压到任意目录，例如 `D:\ffmpeg`。
3. 将 `D:\ffmpeg\bin` 加入系统环境变量 `PATH`，或在程序界面中手动指定 `ffmpeg.exe`。

### 3. 准备模型权重

下载 U²-Net 人物分割预训练权重 `u2net_human_seg.pth`，放置在程序目录下，或通过界面的“浏览”按钮选择。

python virtual_background_u2net.py

## 使用说明

程序启动后，左侧为控制面板，右侧为实时预览窗口。

### 摄像头

- 在“摄像头编号”中选择 `0`（默认）或 `1`（常见外接摄像头）。
- 点击“开始”启动预览；点击“结束”停止预览并释放摄像头和模型。

### 模型与推理

- **权重路径**：默认使用 `u2net_human_seg.pth`，也可浏览选择其他 `.pth` / `.pt` 文件。
- **设备**：可选择 `cuda` 或 `cpu`；CUDA 不可用时会自动回退到 CPU。
- **输入尺寸**：可选 192、256、320、384，默认 320。尺寸越大，效果通常越好但速度越慢。
- **FP16 加速**：仅 CUDA 下有效，可提高速度，边缘质量可能略有下降。

### 背景与画面参数

- **图片背景**：选择 JPG、PNG 或 BMP 图片作为虚拟背景。
- **纯色背景**：使用调色板设置背景颜色，默认蓝色。
- **阈值**：范围 0.00–1.00，默认 0.50。值高会更严格地判定前景；值低更易保留发丝等边缘，但可能残留背景。
- **水平镜像**：勾选后左右翻转画面，适合自拍预览。

### 保存画面

选择保存目录（默认 `outputs`），点击“保存当前画面”即可保存当前合成画面：

```text
YYYYMMDD_HHMMSS.jpg
```

### 录制视频与声音

- 未勾选“录制时包含声音”时，程序直接输出无声 MP4。
- 勾选后，程序通过 `sounddevice` 采集麦克风，并在停止录制时调用 `ffmpeg` 合并音视频。
- 可在“语音 / 声音”一栏的“麦克风”下拉框选择输入设备；点“刷新”重新枚举设备。
- `ffmpeg` 已加入 `PATH` 时，界面中的 ffmpeg 路径可以留空；否则请选择 `ffmpeg.exe`。

文件名格式：

```text
record_YYYYMMDD_HHMMSS.mp4
```

带声音的录制过程：

1. 视频写入临时文件 `_temp_video_*.mp4`。
2. 音频写入临时文件 `_temp_audio_*.wav`（44.1 kHz、单声道、16-bit）。
3. 停止录制时执行：

```bash
ffmpeg -y -i temp_video.mp4 -i temp_audio.wav -c:v copy -c:a aac -b:a 128k -shortest output.mp4
```

4. 合并成功后自动清理临时文件。若找不到 ffmpeg，则保留无声视频并提示。

### 局域网多人会议

程序内置轻量级 LAN 视频会议，采用“**一台主机转发，其他成员连接主机**”的星型拓扑。这样每位成员只需上传一条压缩视频流，避免每人直连每人导致连接数和带宽快速膨胀。

1. 主持人在一台电脑上填写昵称、端口（默认 `49500`）和**人数上限**（2–50，含主持人），点击“创建主机”。界面会显示/预填该电脑的局域网 IP。
2. 其他参会者运行相同程序，填写自己的昵称、主持人的局域网 IP 和相同端口，点击“加入会议”。
3. 所有成员先点击“开始”开启本地虚拟背景预览；本地合成后的画面会自动上传，远端画面显示在下方网格中。
4. 点击“离开”只断开会议，不会停止本地摄像头预览。
5. 连不上时点击会议面板里的“**连接诊断**”，程序会在后台检查四项并给出结论：本机局域网 IP、本机端口监听状态、目标主机能否 `ping` 通、目标端口能否建立 TCP 连接。

人数上限只在**创建主机**时生效，由主机单独设定，默认 18，可调到 50。达到上限后，再加入的人会收到“会议已满（上限 N 人）”并被断开，而不是静默失败。

> **50 人的会议必须选“合成画面”模式。** 逐路转发模式下主机上行带宽随人数近似平方增长：18 人时已经在转发约 290 路视频流，普通千兆局域网就到头了；50 人需要约 2400 路，完全跑不动。合成模式把它降到线性（每人只发一路），50 人约 150 Mbps，千兆网可用。

### 画面模式

创建主机时选择，加入别人会议的一方不用设置（由主机决定）。

| | 逐路转发（relay） | 合成画面（mosaic） |
| --- | --- | --- |
| 主机做什么 | 把每路画面原样转给其他所有人 | 拼成一张多宫格图，只编码一路 |
| 你收到什么 | 其他人的原始 480 × 270，各占一格 | 同一张缩略图墙，从里面切出各自的格子 |
| 主机上行 | 随人数**平方**增长 | 随人数**线性**增长 |
| 单人格子 | 始终 480 × 270，最大最清晰 | 随人数变小（50 人时约 200 × 112） |
| 适合 | 4–8 人，想要看清每个人的脸 | 十几人以上 |

同样的 12 FPS、JPEG 质量 55，主机每秒上行带宽大致是：

| 人数 | 逐路转发 | 合成画面 |
| --- | --- | --- |
| 4 | 5 Mbps | 4 Mbps |
| 8 | 25 Mbps | 20 Mbps |
| 12 | 61 Mbps | 30 Mbps |
| 18 | 147 Mbps | 48 Mbps |
| 25 | 293 Mbps | 82 Mbps |
| 50 | 1220 Mbps | 149 Mbps |

（实测数据，根据单帧 5.2 KB、合成图约 30 KB 换算；内容越复杂帧越大。人数少时两种模式差不多，人越多合成模式的优势越明显。）

合成模式的代价是**所有人看到的是同一张缩略图墙**——不能像转发模式那样把某个人放大。这是把主机上行从平方降到线性的直接交换。想在大会议里看清某个人，需要的是主机端做“只发当前说话人”那类方案，不在当前实现里。

> 合成模式的主要开销压在主机上：它要解码每个人的画面、拼图、再编码一次。人数多时主机的 CPU 会成为新的瓶颈，表现为画面帧率下降。同时降低“发送帧率”和“JPEG 质量”可以缓解。

#### 语音对讲

语音走的是和视频同一条连接，由主机按发送者排除转发，所以谁都不会听到自己的声音。主机不做混音——每台客户端把收到的几路 PCM 直接相加，CPU 开销几乎为零。

- **进会即能听**：创建或加入会议后音频设备自动打开，扬声器持续播放他人语音。
- **默认闭麦**：麦克风虽然已打开，但一块数据都不会上传。点“**开麦**”才开始说话，再点一次回到闭麦。
- **麦克风 / 扬声器**：在“语音 / 声音”一栏里选择，点“刷新”重新枚举设备。麦克风同时供会议语音和本地录制使用。
- **输出音量**：只影响你听到的他人语音，不影响上传。
- 参数为 16 kHz 单声道 PCM，每 20 ms 一块。每人下行带宽 ≈ (人数 − 1) × 256 kbps：18 人约 4.4 Mbps，50 人约 12.5 Mbps，相比同规模的视频仍是很小的一块。

> **需要戴耳机。** 本实现没有做回声消除（AEC）：用外放时，扬声器的声音会被自己的麦克风拾取，再传给其他人，形成回声甚至啸叫。要避免，请戴耳机，或说话时保持闭麦。

诊断失败时的常见对应关系：

| 诊断现象 | 常见原因 |
| --- | --- |
| 能 `ping` 通，但端口连不上 | 对方没有处于“创建主机”状态，或对方防火墙拦住了该端口 |
| `ping` 与端口都不通 | 两台设备不在同一网络，或该网络开启了客户端隔离（手机热点、校园/单位 Wi-Fi 常见） |
| 报 `WinError 10061`（目标计算机积极拒绝） | 目标机器的该端口没有监听：通常是对方未点“创建主机”，或 IP 误填成了 `127.0.0.1`、`192.168.56.1` 这类本机/虚拟网卡地址 |

> 注意：端口输入框与主机**实际绑定的端口**可能不一致（主机创建后再改输入框即会出现）。诊断会指出这种不一致；其他成员必须以主机实际监听的端口为准。

传输策略：每条视频流会先缩放为 **480 × 270**，再按可选 JPEG 质量（默认 55）压缩，并限制为默认 **12 FPS**。每个连接的发送端分成两个队列——控制与语音走优先队列，视频单独排队且只保留最新两帧；网络变慢时丢的是过期画面，语音不会被画面顶掉。所有 socket 都关闭了 Nagle 合并，避免小块的语音被攒着不发。合成模式下主机按同样的帧率拼图、编码一次，客户端只解码这一张。

> 首次创建主机时，请在 Windows 防火墙提示中允许 Python 使用“专用网络”。主机和成员必须处于能互相访问的同一局域网；该实现未提供互联网穿透、身份认证或传输加密，不应暴露到公网。

### 麦克风无法启动

检查 Windows“设置 → 隐私 → 麦克风”，确认允许应用访问麦克风；也可在麦克风下拉框中尝试其他输入设备。

进会时若弹出“无法打开音频设备”，说明麦克风或扬声器被别的程序独占了（常见于另一个会议软件正在运行）。关掉占用设备的程序，或在该下拉框里换一个设备，然后重新“离开”并“加入会议”。

### 会议里听不到别人说话 / 别人听不到我

先确认自己那一路：

- 听不到别人：检查“语音 / 声音”里的**扬声器**是否选对，以及“输出音量”是否为 0。对方必须处于**开麦**状态。
- 别人听不到我：确认已点“**开麦**”（按钮会变成“闭麦”）。只要还显示“开麦”，你说的话就一块都不会发出去。
- 两边都正常但仍有回声：本实现没有回声消除，请改用耳机。

### 会议人数上限

上限在主机那台电脑的“**人数上限**”里设置，只在点“创建主机”时生效；主持后再改这个数字不会影响已经开着的会议。达到上限时，后来的人会看到“会议已满（上限 N 人）”。

### 合成模式下格子太小 / 想让某个人大一点

合成模式所有人看到的是同一张缩略图墙，格子大小由人数决定（50 人时约 200 × 112）。这是把主机上行从平方降到线性的直接交换，不是可以调的参数。人少的时候把画面模式切成“**逐路转发**”，单人格子就是完整的 480 × 270。

### 会议画面卡顿

先看“画面模式”：

- **逐路转发**：人数一多主机就转发不过来。12 人以上建议改用合成模式。
- **合成画面**：带宽不是问题，瓶颈变成主机的 CPU（要解码每个人的画面再拼图编码）。降低“发送帧率”或“JPEG 质量”能明显缓解。

另外确认主机不要跑在 Wi-Fi 上——主机承担所有人的上行，有线连接通常差别很大。

### 录制的视频没有声音

确认已勾选“录制时包含声音”。若临时 WAV 文件有声音而最终 MP4 没有，可尝试在 ffmpeg 参数中增加 `-async 1`。

### CUDA 不可用

程序会自动回退到 CPU，速度会明显降低。请确认安装了 CUDA 版 PyTorch，且显卡驱动支持所用 CUDA 版本。

### 抠图边缘不理想

尝试以下方式：

- 在 0.35–0.65 范围内调整阈值。
- 提高输入尺寸，例如 384。
- 关闭 FP16。
- 确认使用的是人物分割专用权重 `u2net_human_seg.pth`。

## 性能建议

- 默认 320 × 320 在速度与效果之间较平衡；192 × 192 最快。
- 默认每 2 帧推理一次，其他帧复用上一张掩码。
- CUDA 下可启用 FP16 加速。
- 建议摄像头固定为 640 × 360，以降低 CPU 负担。
- 设置 `CAP_PROP_BUFFERSIZE = 1`，减少画面延迟堆积。

## 安全与稳定性

程序会检查模型文件、背景图片、保存目录和摄像头状态；对于空帧、推理异常或 CUDA 异常，会跳过当前帧或降级显示原始画面。关闭窗口时会自动停止线程、释放摄像头并处理录制临时文件。
